## Средняя сложность

### №7 Декоратор для логирования вызова функции

Файл `lab4/logging_decorator.py`.

`log_calls(logger=None)` — декоратор с параметром. Если logger не
передан, используется `logging.getLogger("lab4.calls")`; имя
вынесено в константу `DEFAULT_LOGGER_NAME`, чтобы тесты не
дублировали строковый литерал. Внутри создаётся обёртка через
`functools.wraps`, поэтому `__name__`, `__doc__` и прочие атрибуты
исходной функции сохраняются.

Логирование разделено на три события:

- `INFO` перед вызовом — имя функции, позиционные аргументы и
  именованные аргументы: `call <name> args=(...) kwargs={...}`;
- `INFO` после успешного вызова — возвращённое значение:
  `return <name> -> <value>`;
- `ERROR` при исключении — тип и текст ошибки:
  `error in <name>: <type>: <message>`; после записи исключение
  пробрасывается дальше голым `raise`, поэтому декоратор не
  меняет поведение функции.

Форматирование сделано через `%`-плейсхолдеры, а не f-строки:
logging откладывает подстановку до реальной записи, и при
отключённом уровне сообщение не собирается. Перехватывается
`Exception`, а не `BaseException`, чтобы не логировать
`KeyboardInterrupt` и `SystemExit`.

### №9 Генератор случайных чисел в диапазоне

Файл `lab4/random_range.py`.

`random_numbers(count, low, high, seed=None)` — генераторная
функция, выдающая `count` целых чисел. Границы включительные:
используется `random.Random(seed).randint(low, high)`, а не
`randrange`, поэтому `high` достижим.

Собственный экземпляр `random.Random` создаётся внутри функции на
каждую генерацию: глобальное состояние `random` не затрагивается,
а одинаковые аргументы и seed дают одинаковую последовательность.
При `seed=None` поведение остаётся случайным.

Валидация: `count < 0` и `low > high` поднимают `ValueError` с
понятным текстом. Так как функция генераторная, проверки
выполняются при первом обращении к итератору — это отражено в
docstring и в тестах (вызов оборачивается в `list`).

### №3 Сумма чисел через `reduce`

Файл `lab4/sums.py`.

`sum_numbers(values)` возвращает
`functools.reduce(operator.add, values, 0)`. Начальное значение
`0` — ключевое решение: пустая последовательность даёт `0`, а не
`TypeError`, как было бы без инициализатора. Функция принимает
любой `Iterable`, включая генераторы, и не изменяет входные
данные. Аннотация допускает смесь `int` и `float`.

## Повышенная сложность

### №7 Бесконечный генератор случайных данных

Файл `lab4/infinite_stream.py`.

`endless_random(low, high, seed=None)` — генератор с `while True`,
выдающий целые числа из `[low, high]` без ограничения длины.
Устроен так же, как `random_numbers`: локальный `random.Random` и
включительные границы, поэтому поток воспроизводим при фиксированном
seed. Неверный диапазон (`low > high`) даёт `ValueError` при
старте итерации.

`take(iterable, count)` ограничивает любой итерируемый объект через
`itertools.islice(iterable, count)` и возвращает `list`. `islice`
не читает источник дальше нужного префикса, поэтому бесконечный
генератор не зависает. Отрицательный `count` валидируется и
поднимает `ValueError`; для конечного источника короче лимита
возвращается весь источник.

### №5 Собственный класс-итератор

Файл `lab4/iterator_class.py`.

`ChunkedIterator(items, size)` — класс, наследующий
`Iterator[tuple[ItemT, ...]]`, который отдаёт исходную
последовательность кусками-кортежами. Внутри хранятся:

- `_items` — снимок входа в виде `tuple`, поэтому последующие
  изменения исходного списка не влияют на обход;
- `_size` — размер куска;
- `_index` — позиция следующего куска.

`__iter__` возвращает `self` (объект является собственным
итератором), `__next__` возвращает срез
`_items[_index:_index + _size]` и сдвигает индекс, а после
исчерпания поднимает `StopIteration`. Последний кусок может быть
короче `size`; для пустого входа не выдаётся ни одного куска.

Валидация в конструкторе: нецелый `size` даёт `TypeError`,
нулевой или отрицательный — `ValueError`. Деление на куски
реализовано вручную, без `itertools.batched`, чтобы задание
действительно проверяло написание собственного итератора.

## Принятые решения

- Все пять заданий разложены по отдельным модулям с одной публичной
  сущностью; `lab4/__init__.py` реэкспортирует их через `__all__`.
- Для воспроизводимости везде используется локальный
  `random.Random(seed)`, а не функции модуля `random`.
- Валидация входных данных поднимает стандартные `ValueError` и
  `TypeError` с информативными сообщениями; генераторные функции
  проверяют аргументы при старте итерации, что задокументировано.
- Тесты написаны на `unittest`, без сторонних зависимостей; для
  проверки логов применяется `assertLogs`, для параметров
  итератора — `subTest`.
- Единственная dev-зависимость — `flake8`; runtime-зависимостей нет.
